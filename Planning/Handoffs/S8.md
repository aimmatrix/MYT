## What the screen does

States, in priority order:

1. **Outcome** after a confirm attempt (kept locally, so it survives the parent's plan map updating).
2. Activity or existing plan **loading**, activity or plan **error** (confirming is paused), or **activity not found**.
3. **Existing plan** (`existingPlan` ready and non-null): shows its fixed time and meeting point and one button, `onOpenPlan(plan.id)`. No confirm controls. This reads the plan map, not T5's result, because T5 returns `not-organiser` before `plan-exists` for non-organisers.
4. **No controls, with an explanation**: preview mode, signed out, no organiser set (button: `onNavigate({ name: "setup" })`), not the organiser, or `onConfirm` absent.
5. **Organiser form**: choose a time, set a meeting point, review, confirm.

Details of the organiser form:

- **Time.** Native radios from `activity.timeOptions`. The vote tally and a "Most votes" or "Tied" chip are advice only and never select anything. An option is disabled if `evaluateDraft` returns an `option-*` code for it, or if its start has already passed on the local clock (display-only guard, see below).
- **Meeting point.** Textarea, 1 to 240 trimmed characters via T5. `Activity.suggestedMeetingPoint` prefills the draft and is labelled "a proposal from the activity listing" while unedited. The hint tells people to use a public place and not a home address; nothing requires or inspects an address.
- **Review panel.** Shows the exact time, meeting point and organiser that will be saved, and that they cannot be changed afterwards.
- **Confirm button.** Its label names the chosen time. It is disabled until `evaluateDraft(optionId, meetingPoint).allowed`. The checklist ("Before you confirm") shows Done or Needed with text, not only colour.
- **Double submission.** A ref guard plus `confirmState.status === "pending"` plus the pending button; radios and textarea are locked while saving.
- **Failure.** `onConfirm` rejecting or returning `ok: false` shows the returned message, reports nothing as saved, and leaves the draft exactly as typed.
- **Immutability.** There is no edit, reschedule, cancel or revise path anywhere in the screen.
- **Going.** Creation never marks anyone as going.

**Props S1 and G3 must supply correctly**

- `interestedPeople`: real people only (T2 output). Samples never go here.
- `initialOptionId`: pass `null` unless the organiser explicitly picked a time on the previous screen. **Do not pass the tally's suggested option.** It is read once per activity (mount or activity change), so a value arriving later is ignored on purpose.
- `evaluateDraft`: must read the clock **when called**, not capture `nowMs` at parent render time, or expiry will only show on the parent's next render. S8 re-renders every 30 s and calls it again on click.
- `confirmState`: only `pending` (disables the controls) and `error` (shown if S8 has no local failure) are used. `retry` is not called.
- `onConfirm`: absent in preview and signed-out mode, which shows the explanatory state.

## Workflow convention, not security

Only the designated organiser sees the confirm controls: `currentUser.id === organiserUserId` and `onConfirm` present. This is a workflow convention that follows the app's agreed single-organiser setup. It is **not file-level security**. Any collaborator with write access to the shared folder could write a plan file directly, and the repository's `overwrite: false` plus fresh re-read is the only guard against duplicates (see `Concurrency review.md`). The non-organiser state says this in plain words.

## Remaining limitations and open points

- **London time display is local.** C2's `formatLondon` is not in the library, so the file has a small `Intl.DateTimeFormat("en-GB", { timeZone: "Europe/London" })` helper (`formatWhen`). When C2 lands, replace it and the `Date.parse` calls with C2's formatter and `parseInstant`. Option validity still comes from T5, not from this helper.
- **Display-only expired guard.** T5 checks interest before time, so with too few interested people it cannot flag a past option. S8 disables an option whose start has passed on the local clock so it is not offered. This never allows anything: the parent's rules still decide, and the disable also stops the organiser picking a past option before the group is big enough.
- **Plan-exists via T5.** The `plan-exists` code path is handled (an "Open the existing plan" button) but the normal route to an existing plan is the `existingPlan` prop.
- **Preview.** In preview the screen shows only an explanation; it does not simulate confirming. G7/S1 can add a fixture view if the demo needs one.
- **Names.** The organiser's name comes from `interestedPeople` or `currentUser.name`; if the organiser has withdrawn and is not in the list, the non-organiser message says "Another person is the organiser".
- **Long meeting points.** The textarea has no `maxLength`, deliberately: T5 counts characters after trimming, so the counter and T5's message decide. Pasting 241+ characters shows the error rather than silently truncating.
