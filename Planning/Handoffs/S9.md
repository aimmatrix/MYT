## Exports

`MyPlans`, plus types `MyPlansExtras` and `MyPlansViewProps` (`MyPlansProps & MyPlansExtras`).

G1's frozen `MyPlansProps` carries only `plans: Loadable<PlanCard[]>`, `onOpenPlan` and `onDiscover`. That cannot express going people, an attendance action or interested-only activities, so I added **optional** extras. A bare `MyPlansProps` object still type-checks.

| Extra prop | Meaning |
| --- | --- |
| `goingPeopleByPlanId?: Record<string, Loadable<ParticipantSummary[]>>` | Real people with a `going` record, per raw plan ID. Absent key: the row shows only `PlanCard.goingCount`, with no names. Never pass samples or live viewers. |
| `organisersByPlanId?: Record<string, ParticipantSummary \| null>` | Organiser line. Absent or null hides it. |
| `attendanceStateByPlanId?: Record<string, ActionState>` | Optional parent-owned (G9) write state. The screen keeps its own pending, saved and error state per plan either way. |
| `onSetAttendance?: (planId, "going" \| "declined") => Promise<ActionResult<unknown>>` | Writes the current person's own attendance. Absent in preview and signed-out mode, which hides the buttons. |
| `interestedActivities?: Loadable<Activity[]>` | The parent's selector for "interested, no plan yet". The screen also drops any activity that already has a plan card. Absent hides the section. |

## What it shows

- **Confirmed plans** (not yet ended), soonest first. Each row has a London date block, an attendance chip, the title, London time range, meeting point, organiser, going names and count, the source link and label, and the actions.
- **Interested, no plan yet**: interest-only activities, labelled "You're interested", "No plan yet" and "Not confirmed. You haven't said you're going." They are never listed as plans you are going to.
- **Earlier plans**: ended plans, labelled "Ended", with no attendance buttons and a line saying they can't be changed. A plan with no end time counts as ended 3 hours after it starts (`FALLBACK_DURATION_MS`).
- Empty state with a "Find something to do" action to `onDiscover`.
- Loading skeleton, a load-error banner ("Nothing has been changed"), and a banner when `plans.issues` is non-empty.

## Decisions worth knowing

- **G10's `PlanSummary` component is not nested.** The real one is a whole page: an h1, a "← My plans" button, its own "I'm going / I can't go" buttons and a "What happens next" panel. Ten of them in a list would give ten h1s and duplicate attendance controls. Rows are built from G10's pure `buildPlanSummary` (`domain/planSummary.ts`), which keeps the facts identical, and "Open plan" calls `onOpenPlan` to reach the full page. I treated "compose rather than duplicate" as reusing the builder.
- **"Going" eligibility uses T5's `evaluateAttendance`.** No second rule here. When it denies (plan started or time unreadable) the row shows T5's message and hides "I'm going". "Can't make it" is offered until the plan has ended and is hidden when you have already declined.
- **Attendance writes.** Each row tracks its own pending state, ignores a second click while saving, and on failure shows the error with "Try again" and "Your earlier answer is unchanged, and the plan is still there for everyone". After a success it says "Saved. You're marked as going." only when the persisted `myAttendance` agrees; if it has not caught up yet it says the list updates from the shared files. Declining only calls `onSetAttendance(planId, "declined")`. Nothing here can delete a plan.
- **No ticket claims.** The section note says a going answer is not a ticket or reservation and points to the original listing for booking.
- **No live counts.** The screen has no presence input, and the "Going" figure is the length of the real going list.
- **Source link validity** comes from `getSourcePresentation` through the builder; the screen never builds its own href. A missing activity shows title "Saved plan", keeps the time and meeting point, and explains the listing is gone.
- Long titles and meeting points wrap (`myt-facts dd` and `myt-plan__title` use `overflow-wrap: anywhere`). Only `myt-*` classes from S2 are used. No inline colours.

## Dependencies and blockers (exact)

1. **Missing modules.** `MyPlans.tsx` imports `../domain/planSummary` (G10, present), which imports `./londonTime` (C2), `./cost` (C3) and `./sourcePresentation` (C1). None of those three are in the library yet, so the screen will not build until they land. `identifiers.ts` and `planRules.ts` are present.
2. **G3 does not load attendance for a list.** `useMytData` loads `attendanceByPlan` only for the single `planId` on the route. On the My plans route there is no `planId`, so S1 cannot fill `PlanCard.myAttendance`, `goingCount` or `goingPeopleByPlanId` for every plan from the current hook. G3 (or S1 through a repository selector) needs to load attendance for all plans on this route, using T2's selectors for "real going". Until then the screen would show every plan as "Not answered yet".
3. **S1 wiring**, once the above exists:
   - Derive `PlanCard[]` from `plansById`, `activities` and attendance. `activity` is `null` when the catalogue no longer has it.
   - Pass `onSetAttendance={actions ? (id, status) => actions.setAttendance(id, status) : undefined}`.
   - Pass `onOpenPlan={(id) => onNavigate({ name: "plan", planId: id })}` and `onDiscover={() => onNavigate({ name: "discover" })}`.
   - Pass `interestedActivities` from the current person's own `interested` records, excluding withdrawn ones.
4. After a write, G3 refreshes only the `attendance` slice for the route's `planId`. On this route it needs to refresh the all-plans attendance data too, or the chip will lag.
