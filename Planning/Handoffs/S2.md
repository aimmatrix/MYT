## Design decisions worth knowing

- Palette follows the Lightfern theme through `--lf-*` tokens only. The three interest hues and "warn" are one mid-tone hue each (`--myt-football`, `--myt-karting`, `--myt-cinema`, `--myt-warn`) and every wash and ink is mixed from them with theme tokens. I first used a `prefers-color-scheme` variant and found in the render tool that the OS scheme and the Lightfern theme can differ, which gave dark chips on a light page, so that approach was removed.
- Primary buttons and accent text use `--myt-accent-fill` / `--myt-accent-ink` (accent pulled toward `--lf-content`) because the raw accent is a muted green with weak contrast under white text.
- The option radio is drawn from tokens (`appearance: none`) because native radios follow the OS scheme.
- `Button` `pending` uses `aria-disabled` and swallows clicks rather than the `disabled` attribute, so focus stays put; the label stays in the DOM at zero opacity under a spinner, so the accessible name is stable. It does not announce progress. G9's feedback should.
- `Chip` is a static span unless `selected` or `onSelectedChange` is passed.
- `Field` has no `<form>`. `required` is visual plus `aria-required`; validation messages come from the screen via `error`.
