## Behaviour S1/S5 should know

- **Two groups, two counts, never summed.** "Real participants · N people" and "Demo profiles · M fictional examples". The real group always shows when anyone is supplied (with "No other real participants yet." if only demos exist). The demo group is omitted when there are none. If both are empty it shows the empty state "No one to suggest yet".
- **Demo labelling.** Every sample row carries the chips "Demo profile" and "Fictional" inside the text column (they wrap, never hide), a dashed edge (`myt-person--sample`) and a group note saying they are not real, not online and not counted as interested or going. Nothing says online, new or going.
- **Current user is excluded** from the real list by `currentProfile.userId`, and the note says "not counting you". So the count here can be one lower than S6's "who's interested" count if S5 passes the same people to both. That is intended.
- **Pass `realParticipants` as real people only.** The component does not assume they are "interested"; it calls them "Real participants". If a `userId` appears in both lists the real person wins.
- **Samples are filtered** to those whose `interestIds` include `activity.interestId`, so passing all twelve seeds is fine.
- **Shared interests** are the exact overlap of the viewer's `interestIds` and the person's. With no viewer interests it lists the person's own interests under "Interests". Unknown (`interestIds` undefined on a real summary) shows "Interests not listed". No percentages, personality labels or compatibility claims.
- **Availability** appears only when the person's availability is known and overlaps the keys the activity's `timeOptions` offer: "Listed as available: Weekend day". Otherwise nothing is shown.
- **Fallbacks:** blank name -> "Unnamed participant"; blank or null university -> "University not shared". Rows are keyed by `userId`; duplicate display names stay separate rows and get "Same name as another person in this list".
- **Limits:** 6 real and 3 demo cards visible, each group with its own "Show N more" / "Show fewer" quiet button (`aria-expanded`, `aria-controls`). Expansion is local state and resets when `activity.id` changes. Props and arrays are never mutated.
- Order: most shared interests first, then name, then userId.
