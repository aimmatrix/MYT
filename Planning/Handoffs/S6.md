## Behaviour

- **Primary text:** "I'd go with someone". When interested the same button becomes "Withdraw interest" (danger variant). It is one DOM element, so keyboard focus survives the change. Success headline: "You're interested". It says plainly that this is not going and not a time vote.
- **Callbacks only:** `onSetInterest("interested" | "withdrawn")` is the only write path. A rejected promise is treated as an `io` failure.
- **Persisted state is the source of truth.** There is no optimistic update. After a successful write the confirmed target is held for at most 5 s, only to cover the gap before G3's watcher delivers the record. It is dropped as soon as the `interest` prop matches or the user or activity changes.
- **States:** idle, saving (button `pending`, "Saving…", polite live region), saved ("Saved on this device. Others will see you once it syncs.", clears after 6 s) and failed (`role="alert"` banner with "Try again"). A failure states what is still shown as persisted. The failed target is retried, never a stale one.
- **Duplicate writes:** blocked by a synchronous ref guard plus `actionState.status === "pending"` from G9. Both the pending and the local guard disable repeated clicks.
- **Scope reset:** changing `activityId` or the current user clears the local failure, bridge and saved note. A write still in flight for the old scope is ignored when it resolves.
- **Locked:** `planExists` disables both join and withdraw, with an explanation. `activityAvailable === false` disables joining only. **Decision for the integrator to confirm:** withdrawing from an unavailable activity stays enabled, because it is not a new interest and Architecture lists only "no plan yet" as the withdraw precondition. If you want it frozen, change `blockedByState` in the component.
- **Interest loading or error:** both actions are disabled so a blind write cannot overwrite an unknown state.
- **Preview and signed-out:** with no `onSetInterest`, `mode === "preview"` or a null user, no write button appears. If `onExitPreview` is provided the panel shows "Leave preview to join" (preview) or "Sign in to join" (live, signed out) and calls it. No IDs are ever created.
- **People list:** from `interestedPeople` only. Deduplicated by `userId` (first record wins), never by name. Two people with the same display name stay separate rows with `#1`/`#2` and hidden text "person 1 of 2 with this name". Order is you first, then name, then ID. University shows when present, with "University not shared" when it is null or blank. A blank name shows "Name not shared" and "Profile not filled in yet". The count in the header is the deduplicated list length.
- **Sample guard:** IDs starting `sample:` are always dropped. IDs starting `preview:` are dropped in live mode and allowed only in preview mode. Fictional companions are S10's and are never counted here.
- **Withdrawal copy:** says withdrawal only changes the person's own record, and that a chosen time is kept but stops counting while they are not interested, then counts again on rejoin. This matches the contract ("votes are effective only while that real user remains interested", and withdraw writes a status, never a delete). It does not claim a vote exists.
- **Read issues:** `interestedPeople.issues` shows a "couldn't be read, so this list may be incomplete" note.

## Two-user scenarios for the integrator

1. **Join:** A (signed in, live) opens an available activity with no plan. Press "I'd go with someone". Expect "Saving…", then "You're interested" and a "You" row. Expect `interests/k(a)/k(A).json` with `status: "interested"` and no vote or attendance file.
2. **Other user sees it:** B opens the same activity. After sync B's list shows A once, with A's university. B's count rises. B is not listed until B joins.
3. **Duplicate names:** give two real accounts the same display name. Both appear, as `#1` and `#2`.
4. **Same person twice:** feed the same `userId` twice (or two tabs). One row only.
5. **Withdraw:** A presses "Withdraw interest". Only A's file changes to `withdrawn`. B's file is untouched. A's earlier time vote (if any) stops counting in S7's tally and counts again after A rejoins.
6. **Failure:** make `onSetInterest` return `{ ok: false }` or reject. Expect a visible alert, the old status still shown, and "Try again" retrying the same target.
7. **Double click:** double-click the button quickly. Expect exactly one `onSetInterest` call.
8. **Plan exists:** with a plan, the button is disabled and the lock message shows.
9. **Unavailable activity:** a non-interested user sees no active join. An interested user can still withdraw.
10. **Preview and signed out:** no write button. "Leave preview to join" or "Sign in to join" calls `onExitPreview`.
11. **Sample leak check:** pass a `sample:` ID in `interestedPeople`. It must not appear or be counted.
