## Integration (every callback named)

```tsx
<Onboarding
  mode={model.mode}                              // "live" | "preview"
  currentUser={model.currentUser}                // null when signed out
  onNavigate={router.navigate}                   // called with { name: "discover" } only after a real save succeeds (or when nothing changed)
  profile={model.profile}                        // Loadable<Profile | null>; ready + null = genuinely new user
  saveState={profileSaveAction.state}            // G9 ActionState
  onSave={model.actions?.saveProfile}            // (ProfileInput) => Promise<ActionResult<Profile>>; leave undefined in preview or signed-out

  onExitPreview={() => router.exitPreview()}     // optional, offered inside preview

```

`ProfileInput` sent to `onSave`: `displayName` (trimmed, inner whitespace collapsed, 1 to 40 characters), `university` (same tidy, may be `""`), `interestIds` and `availability` (canonical order, no duplicates, at least one each), `budgetPence` (`null`, `0`, or a positive integer).

## Behaviour

- **Unloaded vs new:** `loading` shows a skeleton and no form. `ready` with `null` shows the empty form. `error` shows the message and no form, so a profile that failed to load is never overwritten blind. If the error code is `invalid-json`, `invalid-record` or `unsupported-schema`, the user can explicitly choose "Start a new profile" (warns that saving replaces the unreadable file).
- **Returning user:** summary of saved values with "Find activities" (navigates, no write) and "Edit preferences". Edit mode prefills everything and offers Cancel (restores saved values, returns focus to Edit).
- **Reset boundary:** the draft lives in a child keyed by `mode` and `currentUser.id`, so changing either starts clean. Inside one boundary the draft is seeded once from the first loaded profile. Later refreshes (new object, same data) are ignored. A refresh with different data replaces the draft only if the user has no unsaved edits. If they do, a "saved profile changed somewhere else" notice with "Use saved values" appears and their edits stay. Our own save arriving back through the subscription is recognised and ignored.
- **Save:** validates locally, awaits `onSave`, keeps every value on `{ ok: false }` or a thrown error, shows the message with "Try again". Repeated clicks while saving, and while `saveState.status === "pending"`, do nothing. Inputs are disabled while saving. Completion is not reported and `onNavigate` is not called until `onSave` resolves `ok: true`. "Find activities" with an unchanged saved profile navigates without writing.
- **Budget:** blank is `null` (no limit). `0`, `0.00`, `£0` are `0` and stay `0` through save and re-edit. `12.5`, `£12.50`, `£1,200` parse to pence with integer arithmetic. Rejected: negatives, letters, exponents, more than two decimals, anything over £10,000.
- **Privacy:** no birthday, address or email field. The panel says everyone using the shared app can see name, university and interests. Display name is pre-suggested from `currentUser.name` for a new live user only; it is editable and is never used as an ID.
- **Preview and signed-out:** preview shows an explanation and "Browse activities" (navigate only, no form, no write) plus "Leave preview" when `onExitPreview` exists. Signed-out explains that sign-in is needed and offers "Look around in preview" when `onEnterPreview` exists. Signed in with no `onSave` says saving is unavailable. None of these invents a user ID or writes a profile.
- **Accessibility:** native `<input>` and `<button aria-pressed>` chips inside `fieldset`/`legend`; labels, hints and errors linked with `aria-describedby`; no `<form>`. A validation summary (`role="alert"`) takes focus on a failed submit, the Edit button takes focus after Cancel, and the first field after Edit. A polite status line announces "Saving your preferences…".

## Dependencies and unresolved points

- G9's `Feedback.tsx` and `useAsyncAction.ts` did not exist when I built this, so the screen renders its own banners from S2's `myt-banner` classes and does not import G9. If G9 lands, S1 can swap `Banner` for G9's component; the `saveState` prop is already consumed (a `saveState` error is shown only after this screen has attempted a save).
- Interest and availability labels are local constants (`Football`, `Go-karting`, `Cinema`; `Weekday evenings`, `Weekend days`, `Weekend evenings`). If C5's `availability.ts` is imported later, its labels should be used so Discover and Onboarding agree.
- University is optional (the contract allows blank); display name, at least one interest and at least one availability are required. Say if the product wants availability to be optional.
- A malformed own profile may reach this screen as `ready` with `null` plus an issue rather than as an `error`, depending on G3. The screen ignores `issues`. If that matters, G3 should return `error` for the signed-in user's own unreadable profile.
- The screen does not retry loading, because `OnboardingProps` has no reload callback.
